About this benchmark
What the terms mean (turn, step, single-turn, multi-turn, …)
How a task runs
Agent
A loaded model (A = baseline, usually full precision; B = quantized) that answers by calling tools. Both agents get exactly the same task, tools and settings.
Task
One benchmark item: a request (or a short conversation), the tools the agent may use, and a reference solution to grade against.
Turn
One user message. The agent works on it, possibly over several steps, until it replies without calling a tool; then the next user message arrives.
Step
One reply generated by the model. A step can contain several tool calls (for example two mv calls at once). The tool results are given back to the model before its next step.
Tool call
A request to run one function with arguments, such as cd(folder='document'). The page shows each call with its result.
Single-turn
The task is one user message and the agent gets one reply. Used to test whether the model picks the right function and arguments.
Multi-turn
The task is a conversation of several user messages that build on each other, and the tools keep state across turns (files created in turn 1 still exist in turn 2).
Multi-hop
One question that needs a chain of tool calls, where each call uses the previous answer (find the park, then its designer, then his first name, then count the letters).
Trajectory
Everything an agent did on a task, in order: every step, call, result and final answer. This is what the turn-by-turn view draws.
Reference
The benchmark's own solution, shown in the first column: the expected calls (BFCL multi-turn), the accepted call(s) and argument values (BFCL single-turn), or the expected chain of intermediate answers (ToolHop).
Settings
Max steps per turn
The most replies the agent may make for one user message before the turn is cut off ("step limit"). Defaults follow each benchmark: 20 (BFCL multi-turn), 9 (ToolHop), 1 (single-turn).
Max new tokens per step
The longest reply the model may write in one step. A reply cut off here usually leaves a broken tool call.
Temperature
0 means always the most likely token (repeatable runs); higher values add randomness.
Loop guard
Ends a turn early when this many steps make the identical call (same function, same arguments), so a stuck model doesn't burn all its steps. 0 turns it off. Repeats inside one reply count once.
Run the agents
One after the other gives each agent the GPU alone, so speeds are comparable. At the same time is faster overall, but each agent runs slower.
Native / prompt-based tool calling
Native: the model's chat template knows tools and the model was trained to call them. Prompt-based: the tools are described in the system prompt for models without tool support.
Reading the trajectory
Action letters
R read (environment unchanged) · W write (changed the environment) · E the tool returned an error · U called a tool that doesn't exist · C call checked but not executed (single-turn) · A plain-text answer, which ends the turn · X output that couldn't be parsed. The row of letters under each agent is its whole run at a glance.
✓ / ✗ per turn
Whether that turn passed the benchmark's check: environment state matches (multi-turn), call accepted (single-turn), correct final answer (ToolHop). Greyed checks come after the first failure and don't count.
Green edge on a call
The agent made exactly the same call as the reference in that turn.
Flags
Warnings pinned to the step where they happened: repeat loop (same call 3×), error persists (the same failing call again), unknown tool, format error, answered without acting, step limit, loop guard.
First divergence
The first call where A and B did something different, and where each first departed from the reference. Useful for seeing where quantization changed the agent's path.
Timeline
Each box is one step; its width is the time the model spent generating it and its colour is what the step did.
Results
Accuracy
Share of tasks fully correct: every turn passes (multi-turn), the call is accepted (single-turn), or the final answer is right (ToolHop).
Turns done
Turns passed before the first failure. Partial credit for multi-turn tasks: 3 / 4 means it went wrong only in the last turn.
Tool calls / ref
Calls the agent made next to the calls (or hops) in the reference. Many more usually means flailing; fewer means it skipped work.
Failure mode
One reason per failed task, decided at the first failing turn: wrong end state, tool errors, missing expected result, answered without acting, stuck repeating a call, step limit, wrong function / parameters / values / number of calls, called a tool when none fits, wrong or no final answer.
Flips (history)
Tasks where only one agent passed. "Only A passes" means the quantized model lost a task the full-precision one solved.
